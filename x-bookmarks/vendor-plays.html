Migration

ExxonMobil · Hypothesis

Code around the Snowflake estate

Why it fits
ExxonMobil's Central Data Office built its enterprise data ecosystem on Snowflake, and Snowflake's January 2026 energy release names ExxonMobil. A Snowflake footprint means pipelines, stored procedures, SQL and downstream apps that someone has to keep converting as data products move in.
Motion
Do not pitch against Snowflake. Position Devin as capacity for the code work its migration tools leave over: SnowConvert AI converts SQL; Devin handles the surrounding application code, orchestration, tests and cutover scripts. Enter through the Central Data Office or the S/4HANA data work, not IT infrastructure.
Who
Central Data Office (Andrew Curry's group), Global Business Solutions data leaders. Ask who owns the pipelines feeding Snowflake.
Sources
Computer Weekly (2023-10), Constellation Research (2024-11), Snowflake (2026-01-27), Snowflake (2026-02)
Not found / caution
No public record of a specific ExxonMobil migration project. The play is a hypothesis built on the footprint. DreamFactory's ExxonMobil case study is vendor-written and unverified, so do not cite it to the customer.
Ties to playbook

Real-time analysis and remediation

ExxonMobil, Enterprise Products, Chevron · Product-ready, account fit unproven

Oncall for alert-to-fix

Why it fits
Devin Oncall launched Oct 15, 2026 with Dynatrace as a launch partner. Devin can read Dynatrace problems, root-cause findings, logs, traces and deployment events, and open a pull request. Datadog is wired in through an MCP integration plus a webhook bridge. AngelList is cited putting Devin on its rotation.
Motion
Make it vendor-neutral: whatever APM or alerting each team runs, Devin plugs in. The discovery question is which tool fires the alert and who carries the pager. Start with one low-severity monitor, as Devin's own Datadog guide recommends, and measure root-cause time and merged PRs.
Who
Application support and SRE leads. At ExxonMobil, ServiceNow and Kubernetes appear in postings; at EPCO, nominations and scheduling failures cost money directly.
Sources
RuntimeWire (2026-10-15), Dynatrace (2026-10-15), Devin docs (current), Your library (2026-10-16), The Stack (2024-08)
Not found / caution
No public evidence that any target account runs Dynatrace, Datadog or New Relic. The integrations for New Relic, Splunk, Elastic and PagerDuty came from earlier research on Devin's release notes and were not re-read this session. Confirm them with your solutions engineer before naming them to a customer.
Ties to playbook
On-call and incident response: enterpriseproducts scores 2/3 (Nominations, scheduling and measurement run the business). Storylines: From One Agent to Thousands, Agents Clock In at Real Companies.
Any account running Datadog, Dynatrace or New Relic · Depends on discovery

Fix half of the observability vendors' diagnose half

Why it fits
Datadog's Bits AI SRE (Dec 2, 2025) investigates alerts and delivers a likely root cause before the engineer logs in. Its release does not mention opening a pull request. Dynatrace says its root-cause analysis is deterministic, so an agent can act on it.
Motion
Frame Devin as the step after the diagnosis: take the root cause, write and test the fix, open the PR for human review. Where a customer already pays for an observability agent, this is additive; where a vendor ships its own coding agent, expect competition and check before promising.
Who
Observability platform owners and SRE directors; they hold the vendor relationship and can sponsor an integration pilot.
Sources
Datadog (2025-12-02), Dynatrace (2026-10-15), Devin docs (current)
Not found / caution
Datadog's page names no third-party coding agents. The Devin-Datadog path that is documented is the MCP integration, not a vendor-announced partnership.
Ties to playbook
On-call and incident response: chevron scores 2/3 (Operational systems across a consolidated IT model). Storylines: From One Agent to Thousands, When Agents Act, Security Becomes the Gate.

Security

Halliburton, Enterprise Products, ExxonMobil · Strong fit for Halliburton and EPCO

Vulnerability backlog program

Why it fits
Cognition's six-week program (Jul 2, 2026) puts forward-deployed engineers with the customer to clear a scanner backlog as validated pull requests, then run Security Swarm for logic flaws scanners miss. It reads Snyk, SonarQube, Checkmarx, Semgrep, Wiz and Veracode output. Halliburton's August 2024 breach (about $35M) and EPCO's TSA pipeline directives are the pressure points.
Motion
Use as the expansion step after a first Devin deployment, since eligibility is enterprise Devin Cloud customers at meaningful scale. Discovery: which scanner, how big is the backlog, who owns merge approval. Pair with Devin's isolated machines to answer IT and OT security questions early.
Who
Application security and engineering leaders; at Halliburton, whoever owns post-breach remediation.
Sources
Cognition (2026-07-02)
Not found / caution
No fix-rate or time-to-remediate figures are published, and no customers are named. The program page does not state pricing. No scanner vendor is confirmed at any target account.
Ties to playbook
Security backlog remediation: halliburton scores 3/3 (August 2024 breach, about $35M). Storylines: When Agents Act, Security Becomes the Gate, From One Agent to Thousands.
